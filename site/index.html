Fault

Software agents fail the moment they touch the real world.

Computer-use stacks browse until they hit a curb: in-store pickup, a phone gate, CAPTCHA, or a clerk who wants a human. Then the session dies. There is no real-world bridge.

Clearance

Escrow-backed shopping with a masked, blind runner.

Bopcart is built to keep spend inside policy bounds, inject payment tokens the model never sees, hold funds in escrow, and dispatch a masked human only when the clean path is blocked.

Stack

Five layers. One signed audit trail.

01

Policy Control

No session and no tool call until a compiled policy check says the intent is in bounds.

Per-ticket spend cap · vendor allowlist · bounded retries before escalation

02

Just-in-Time Token Injection

Sensitive personal data is stripped before the model. Cards and addresses enter the HTTP client inside an isolated sandbox, never the prompt.

Ephemeral merchant tokens · reasoning chain stays secret-blind

03

Escrow Settlement

Designed for 2-of-3 escrow: buyer key, Bopcart arbiter key, merchant/processor key. Funds release when the order is confirmed.

Bopcart as clearinghouse, not a message board

04

On-Demand Human Fallback

Triggered by physical errands, voice confirmation, or bot walls. A masked runner opens a scoped micro-task link and never sees the buyer.

Masked runner · isolated worker sandbox

05

Proof Continuity

Every purchase, hold, or dispatch appends a leaf to an append-only log. Both sides get tamper-evident signed receipts (post-quantum signing in development).

leaf id · session · actor · payload hash · policy hash · prev hash · settlement · signature
